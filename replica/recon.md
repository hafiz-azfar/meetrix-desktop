# Meeting workflow research

The Windows installation reported Zoom Workplace 7.1.9 (48550). REA inspected the PE resource inventory for its local launcher without reconstructing source or unpacking assets. Three Computer Use captures document the installed client's home, join dialog, and schedule form. The captures contain account information and stay in the locally ignored `replica/screens` directory.

After checking Zoom's terms, the feature comparison used public product descriptions. Zoom software, accounts, service endpoints, graphics, and UI code are absent from Meetrix. [Zoom terms](https://www.zoom.com/en/trust/terms/) · [Zoom Workplace plans](https://www.zoom.com/en/products/virtual-meetings/)

| Workflow | Gathered evidence | Meetrix route |
|---|---|---|
| Start a meeting | Windows home shows a meeting action and calendar | Overview → New meeting → preflight → room |
| Join a meeting | Windows join dialog takes an ID or personal link and offers media options | Invite or Join a room → preflight → waiting room → call |
| Schedule | Windows form shows start/end time, timezone, recurrence, and invitees | Meetings → Schedule → iCalendar invite |
| Run a meeting | Public Zoom product descriptions cover audio/video, screen sharing and collaboration | Call stage and People, Chat, and Notes panels |
| Manage admission | Public Zoom security material covers passcodes, waiting rooms, and host controls | Preflight and the host's People panel |
| Use Pro features | Public comparison covers extended duration, cloud storage, AI, and additional workspace tools | Coverage detail in the feature matrix |

The Windows captures establish those three screen states. Account-gated features and meeting-scale behavior are documented through public sources.
